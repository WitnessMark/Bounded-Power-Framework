# Reference

Supporting material for the Bounded Power Framework: background, assessments, maintainer resources, and data.

**This folder explains and supports the framework. It does not define it.** The binding text is the Core Requirements ([SCBP-04](../01-Framework/SCBP-04-Core-Requirements.md)). How to apply them is in the Operations Manual ([SCBP-03](../01-Framework/SCBP-03-Operations-Manual.md)) and the [forms](../02-Forms/). Where anything here seems to differ from those, they govern.

If you are new, start with [Start Here](../00-Reading/00-Start-Here.md) and [What This Is and Is Not](../00-Reading/02-What-This-Is-and-Is-Not.md).

---

## Framework background — [`01-Framework-Background/`](01-Framework-Background/)

Why the framework exists, how its parts fit together, and how to think about its central idea. Context, not rules.

## Analytical standards — [`03-Analytical-Standards/`](03-Analytical-Standards/)

The [Stop-Path and Protections Reference](03-Analytical-Standards/Stop-Path-Protections-Reference.md): a longer list of the ways people can try to stop or challenge an authority's action. It supports the plain-language guide [What You Can Do](../00-Reading/07-What-You-Can-Do.md). It is not legal advice.

Deeper guides that add examples and common mistakes to the Operations Manual. The manual is the procedure; these are reference:
- [Visibility Sufficiency Standard](03-Analytical-Standards/Visibility-Sufficiency-Standard.md): what "knowable to those affected" means (3.B.9).
- [Threshold Definition Handbook](03-Analytical-Standards/Threshold-Definition-Handbook.md): writing a threshold with all five parts (3.A.5).
- [Renewal Evidence Standard](03-Analytical-Standards/Renewal-Evidence-Standard.md): what evidence a renewal needs (3.E.2, 3.E.3).
- [Authority Surface Mapping Guide](03-Analytical-Standards/Authority-Surface-Mapping-Guide.md): mapping a power's six dimensions of growth (3.B.1).
- [Structural Failure Casebook](03-Analytical-Standards/Structural-Failure-Casebook.md): recurring patterns of failure, with generic illustrations.

## Assessments — [`04-Assessments/`](04-Assessments/)

Examinations of the framework, made at a particular time. They are evaluations, not requirements. This is where independent reviews of v1 belong. It starts with [Standing Positions](04-Assessments/Standing-Positions.md), which says which choices are deliberate and which questions are open, and a short answer to the strongest objection to the framework: that it is circular.

## Maintainer resources — [`05-Maintainer-Resources/`](05-Maintainer-Resources/)

- **Hash registry.** A SHA-256 fingerprint of every published file outside this `05-Reference/` folder, kept current automatically (Core Requirements 6.5). Check any file with `sha256sum FILE`. A file that differs from its registered fingerprint is not an official version. The registry file is created by the repository workflow on first publication; until then, no fingerprints are recorded.
- **Canonical text standard.** The file format rules that keep fingerprints stable.

## Supporting data — [`06-Supporting-Data/`](06-Supporting-Data/)

Historical datasets behind the framework's patterns. They are read for the reader in [Historical Context](../00-Reading/03-Historical-Context.md). They are history, not records under the framework and not findings about anyone or any institution.

## Templates — [`Templates/`](Templates/)

The [Human Review Summary](Templates/Human-Review-Summary.md): a template for writing down what a person checked in a record, covering the checks the checker cannot make. A review does not certify or change a record.

## Assets — [`Assets/`](Assets/)

Images used by the repository.

## What is not here

- **No records of real institutions.** v1 holds only worked examples ([03-Examples](../03-Examples/)) and BPF's own record ([04-Registry](../04-Registry/)).
- **No registry operating rules or submission process.** v1 has no place to submit records or reports.
- **No checker or builder.** They live with the forms in [02-Forms](../02-Forms/). What the checker can and cannot check is set out in the [Validator Coverage Matrix](Validator-Coverage-Matrix.md).
